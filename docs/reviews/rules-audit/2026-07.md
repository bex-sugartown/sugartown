## Editor's verdict

Two failure classes recurred in this run and both are worth naming before the table: (1) the exact "MCP tool name that no longer exists" bug that originally motivated this epic is still live in 6 places — 3 content-writing skills, their shared pipeline doc, and 2 MEMORY.md files all cite `create_documents_from_json`/`create_documents_from_markdown`/`patch_document_from_json`, none of which exist; only `create_documents`/`patch_documents` do. (2) The audit's own first-pass inventory subagent missed 2 of 17 skill folders on its first attempt — caught only because the orchestrating session recounted by hand. Both are reported plainly below rather than smoothed over, because a governance audit that undercounts its own corpus on run 1 is exactly the kind of silent-drift the PRD exists to catch.

The good news: the contradiction sweep that mattered most — whether the `/glossy` auto-publish bug recurs anywhere else — came back clean. Every content-writing skill stops at the draft; nothing calls `publish_documents`/`unpublish_documents` without the explicit standalone instruction the Human-Publishes Rule requires. The Instruction & Rule File Write Gate has already fired twice in real sessions (SUG-215, SUG-210) and caught the violation both times. Gate efficacy across all 15 reviewed hard-stop/blocking gates found zero candidates for outright retirement — but did find one clean merge (Taxonomy pre-flight → Atomic Reuse Gate) and one real simplification opportunity (Atomic Reuse Gate's CSS/component territory has been fully superseded by two more specific, better-enforced descendant gates and is now duplicated effort, not defense in depth).
