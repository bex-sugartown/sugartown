1 · Findings

  1. Surface. The banner fills with --st-card-label-bg. In light that is neutral-200 #e4e4e5 on a neutral-100 #f2f2f3 page, 1.14:1. Its 1px --st-color-rule-accent sides are 1.52:1. In dark, midnight-800 on midnight-900 is 1.06:1 and the rule 1.55:1. Only the pink top rule passes 3:1 in both themes. The float shadow is 10% opacity in light.
  2. Meta line fails today. "Current choice: accepted" is --st-color-text-muted #6c6c6f on #e4e4e5: 4.12:1, below AA for 12px text. SUG-202 §4 did not measure it.
  3. Bottom clearance is applied but never takes effect. ConsentBanner.jsx sets document.body.style.paddingBottom to the bar height. apps/web/src/design-system/styles/globals.css sets body { height: 100% }, so body is one viewport tall and the page content overflows it. The padding sits inside that one-viewport box and adds no scroll room after the footer. #root is min-height: 100vh with auto height, so padding there does extend the scroll.

Clearance: in ConsentBanner.jsx, apply the measured padding to document.getElementById('root') instead of document.body (two lines: set and cleanup). Behaviour, measuring and ResizeObserver are unchanged. Not chosen: changing body to min-height: 100% in globals.css, which reaches every page and every height: 100% descendant.

Scope tension: the epic lists the clearance as web CSS. The root cause is the JS target, so the fix is a one-line JS change. Approve or redirect.
