# SUG-184 — GSC "Crawled - currently not indexed" — resolve all causes

Google Search Console shows 18+ URLs in the "Crawled - currently not indexed" report. These are pages Google visited but chose not to index — which means they either have thin/duplicate content, are parameterised filter states that shouldn't be indexed at all, or point to non-existent routes. This epic resolves all four root causes identified from the example list.

## Root causes

### Cause A — Parameterised filter URLs crawled and submitted to index

No `robots.txt` exists. Google freely follows filter state URLs (`?project=`, `?category=`, `?tag=`) generated by the knowledge graph, archive pages, and homepage filters. These URLs produce no unique content — they are SPA filter states that render the same page with a subset of items. They should never appear in the index.

### Cause B — Thin taxonomy and tool detail pages

Tag, category, and tool detail pages with fewer than ~3 linked content items contain almost no unique text. Google's quality threshold for indexing is higher than "page exists." The `resolveSeo()` function defaults to `robots: { index: true }` for all taxonomy docs — there is no minimum-content threshold.

Two sub-paths:
- **B1 — Code fix:** add a content-count threshold to TaxonomyDetailPage and ToolDetailPage: if fewer than 3 linked items, set `robots: { index: false, follow: true }`. Self-healing — once a tag accumulates enough content, it gets indexed automatically.
- **B2 — Content enrichment (editorial):** add descriptions to taxonomy docs in Sanity. Tags and tools with authored descriptions provide enough unique content to pass Google's quality bar regardless of linked-item count. This is a separate editorial pass, not a code change.

### Cause C — Bad link to `/gem/` namespace

`/gem/release-governance-yyyy-mm-dd-workflow/` is a 404 — the `/gem/` route does not exist in `App.jsx`. Google crawled it, meaning a link to this URL exists somewhere in the published content (likely a node or article body). At activation, find the source link, then either: (a) fix the link in Sanity, or (b) add a redirect in `_redirects` if the URL was intentional and the route needs creating.

### Cause D — `/about` thin content

The `/about` page is a standard `RootPage` pulling from a Sanity `page` doc. If the Sanity doc has minimal sections or empty body fields, Google sees thin content. Fix: enrich the `/about` page content in Sanity (editorial, not code). Check the doc in Studio first — if it's missing sections, add them.

### Non-issue — `/articles/headless-cms-schema-where-it-lives`

Crawled Jun 12 before SUG-183 deployed. The prerender script now writes static HTML for all article routes at build time. This URL will self-heal on Google's next crawl after the next Netlify deploy. No action required.

## Objective

After this epic, the GSC "Crawled - currently not indexed" list is either empty or contains only URLs that are genuinely low-priority (e.g. tags with 1 linked doc that haven't yet crossed the content threshold — acceptable). All parameterised filter URLs are blocked at robots.txt level. The `/gem/` 404 source is found and fixed. Thin taxonomy pages are automatically noindexed below the threshold.

## Technical notes

- **robots.txt location:** `apps/web/public/robots.txt` — Vite copies `public/` verbatim to `dist/` root. Netlify serves it at `https://sugartown.io/robots.txt`.
- **Thin-content threshold constant:** name it `MIN_INDEXABLE_ITEMS = 3` at the top of each page file. Do not hardcode 3 inline — the value may need tuning.
- **GROQ query for `/gem/` link hunt:**
  ```groq
  *[_type in ["article", "node", "caseStudy"] && defined(sections)] {
    _id, _type, title, "slug": slug.current,
    sections[]{
      _type,
      content[]{
        _type,
        markDefs[href match "/gem/*"]{ href }
      }
    }
  }
  ```
  Also check `body` field (nodes use direct PT body). Also check `htmlSection.html` fields for raw `href` strings.
- **`SeoHead` already supports `robots: { index: false }`** — `resolveSeo()` in `src/lib/seo.js` reads `docSeo.noIndex`. The page-level override bypasses `resolveSeo` entirely: pass `robots: { index: false, follow: true }` directly into the `seo` object that `SeoHead` receives.
- **robots.txt `/*?*` syntax:** Googlebot supports wildcard `*` in Disallow paths. `Disallow: /*?*` blocks any URL containing a `?`. This is intentionally broad — sugartown.io has no URLs where query params are canonical. If a future feature needs indexable query params (unlikely), update robots.txt at that time.
- **SUG-183 self-healing:** `/articles/headless-cms-schema-where-it-lives` does not need a GSC re-index request — Googlebot will recrawl it on its normal schedule and see real HTML. Flag it in Phase 3 only if it hasn't cleared within 4 weeks post-deploy.
- **Merge strategy:** (a) each phase merges to main independently. Phase 1 is a single commit checkpoint covering 1A+1B+1C together (small, cohesive). Phase 2 is a Sanity-only content edit, no code commit needed. Phase 3 is a verification pass, no code.
- **Model & Mode:** Sonnet execution. No complex architecture — this is a targeted fix pass across three surfaces (robots.txt, two page files, one Sanity GROQ audit). No Phase 0 mock required (no new visual surfaces).
