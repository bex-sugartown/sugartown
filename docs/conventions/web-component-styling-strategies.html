Web component
styling strategies

Every web component draws a line. On one side is structure the author controls; on the other are surfaces the consumer is allowed to touch. These five strategies move that line.

← strictest · total encapsulation no boundary · loosest →

01

Locked

--nys-* vars

The component seals its structure and exposes a documented list of CSS custom properties. Internally, private --_nys-* variables fall back through a public --nys-* hook to a design token. Consumers retheme through those names and cannot reach anything else.

button badge checkbox radio spinner 
/* Author */
:host {
  --_nys-btn-bg: var(--nys-btn-bg, var(--nys-color-theme, #1b4965));
  --_nys-btn-radius: var(--nys-btn-radius, 6px);
}
button { background: var(--_nys-btn-bg); }

/* Consumer — only published hooks reach inside */
nys-button.danger {
  --nys-btn-bg: #9b2226;
  --nys-btn-radius: 999px;
}
Limit: Consumers can change only what you declared. Any internal node without a published variable stays sealed — which is exactly the guarantee you want for atomic controls.

02

Themeable

::part()

The author tags internal elements with a part attribute to publish them by name. Consumers restyle with host::part(name) — no knowledge of the shadow tree required. The selector stops at the parted node and will not descend further.

tabs accordion select dialog toast 
/* Consumer */
nys-tabs::part(badge) { background: #9b2226; }

/* ✗ Does nothing — can't descend into a part's shadow children */
nys-tabs::part(tab) span { color: red; }

/* ✓ Fix: give the descendant its own part attribute */
nys-tabs::part(label) { color: #9b2226; }
Limit: ::part() can't select a descendant of a part. The fix is a new part attribute on the descendant, not a fancier selector.

03

Themeable + nested

exportparts

::part() only crosses a single shadow boundary. When a component renders another component inside its own shadow root, the inner part is invisible from the page. exportparts re-publishes the child's part through the parent's boundary — optionally renaming it — so the page can reach two levels deep.

alert-with-action card-with-button compound components 
/* Parent shadow root */
<nys-mini-button
  exportparts="label: forwarded-label">
</nys-mini-button>

/* ✗ Raw child name doesn't cross the parent boundary */
nys-alert::part(label) { color: red; }

/* ✓ Re-published name — two shadow roots deep */
nys-alert::part(forwarded-label) {
  color: #9b2226;
  text-decoration: underline;
}
Limit: Forwarding is explicit, one hop at a time. Three-deep nesting means the middle component must forward again.

04

Slotted

<slot> + light DOM

A slotted frame keeps the consumer's content in the light DOM and projects it through named slots. Because that content never crosses the shadow boundary, the consumer styles it with completely normal CSS at any depth. ::slotted() can set baseline styles, but only on the top-level projected node — not its children.

card panel modal body rich content wrappers 
/* Consumer — normal CSS, any depth */
.body-content p .pill { background: #e2f1e8; }

/* ✗ ::slotted() only reaches top-level projected node */
::slotted([slot="body"] *) { color: red; }

/* Never reparent slotted content into the shadow root */
/* — you silently demote the consumer to a guest behind your wall */
Limit: ::slotted() sees top-level projected nodes only. Descendants are out of reach — but normal page CSS isn't, because the content never left the light DOM.

05

Light DOM

createRenderRoot

Overriding createRenderRoot() to return this renders the component directly into the page DOM — no shadow root is created. static styles is ignored; all styling comes from the page. Full reach, zero isolation.

data tables generated lists grids unpredictable structures 
class NysDataTable extends LitElement {
  createRenderRoot() {
    return this; // No shadow root — page CSS hits everything
  }
}

/* Consumer — plain selectors, no ::part() needed */
.nys-dt thead th { background: #16202e; }
.nys-dt tbody tr:nth-child(even) { background: #faf8f2; }
Limit: Nothing is scoped. Global CSS can hit these elements by accident. Acceptable only when the component emits structure no fixed set of parts could enumerate.

// decision guide

If you need... Use Strategy
Fixed design, no consumer theming --nys-* vars 01 Locked
Consumer rethemes named pieces ::part() 02 Themeable
Those pieces live inside a child component exportparts 03 Themeable + nested
Consumer brings their own rich content <slot> 04 Slotted
Component generates unpredictable structure createRenderRoot 05 Light DOM

// key rules

  • →Never reparent slotted content into the shadow root. Doing so silently demotes the consumer from author of their markup to a guest behind your wall.
  • →::part() stops at the parted node. You can't descend into a part's shadow children. The fix is a new part attribute on the descendant, not a fancier selector.
  • →exportparts is one hop at a time. Each boundary in the chain must explicitly forward. Raw child part names do not cross the parent boundary automatically.
  • →::slotted() sees top-level projected nodes only. Descendants are out of reach via ::slotted() — but normal page CSS isn't, because slotted content never left the light DOM.
  • →Light DOM removes all style isolation. Use it only when the component generates structure that no fixed set of part attributes could anticipate.

// glossary

shadow DOM
A separate, encapsulated subtree attached to a host element. Internals are hidden from the main document — normal CSS selectors and document.querySelector can't reach inside. Created by a web component via attachShadow(). The boundary it draws is the core subject of this document.
light DOM
The regular document tree — the HTML you write in your page. The term only means something in contrast to shadow DOM. Slotted consumer content stays here; Light DOM components render here entirely.
shadow boundary
The line between the host element and the shadow root. Normal CSS cannot cross it. Only --custom-properties, ::part(), exportparts, and ::slotted() provide controlled crossing points.
custom properties
CSS variables (e.g. --nys-btn-bg) that cross the shadow boundary by design. They "inherit" through the boundary, making them the lowest-overhead way to expose theming hooks from a sealed component.
::part()
A CSS pseudo-element that lets a consumer style a specific internal element the author tagged with part="name". Stops at the parted node — cannot descend further into the shadow tree.
exportparts
An HTML attribute that re-publishes a child component's part names through the parent's shadow boundary, optionally renaming them. Allows styling two shadow roots deep from the page.
::slotted()
A pseudo-element authors use to style content projected into a slot. Can only select the top-level slotted node — not its descendants. Consumers can style slotted content's descendants with normal CSS because it never left the light DOM.
<slot>
A placeholder inside a shadow root that projects the host element's light DOM children into position. The content is displayed inside the component but remains owned by the consumer's document.
createRenderRoot()
A Lit lifecycle method that controls where a component renders. Overriding it to return this skips shadow root creation, rendering the component directly into the light DOM. static styles stops working; all styles come from the page.
host element
The custom element in the consumer's markup (e.g. <nys-button>) that owns the shadow root. Styles applied to it from outside can reach the shadow internals only through the strategies documented here.
static styles
A Lit class property that injects a CSSStyleSheet into the shadow root. Scoped to that component; invisible to the rest of the page. Has no effect when createRenderRoot() removes the shadow root.
web component
A suite of browser standards (Custom Elements, Shadow DOM, HTML Templates) that let you define reusable, encapsulated HTML elements with their own markup, styles, and behaviour.
