# Alignment Audit — Sugartown AI Workflow vs. Maven "AI Product Management Certification"

**Date:** 2026-07-01
**Standard source:** [maven.com/product-faculty/ai-product-management-certification](https://maven.com/product-faculty/ai-product-management-certification)
**Scope of ecosystem reviewed:** `CLAUDE.md`, `docs/epic-template.md`, `docs/ai/README.md` and `docs/ai/agentic-caucus/` (methodology, risk-tiers, agent-cards, governance-coverage, incident-log, data-handling), the Claude Code agent/skill/subagent system as used in this repo (Agent tool, Explore agent, Workflow tool, `design-reviewer` subagent), and the mini-release/epic close-out process.

## Summary

11 dimensions extracted from the course; 3 Match, 4 Drift, 3 Gap, 1 N/A. The single biggest finding is a **framing mismatch, not a maturity gap**: the course teaches PMs how to identify, design, and ship AI-*powered features inside a product for end users*. Sugartown's ecosystem uses AI (Claude Code) as an *internal development tool* to build a non-AI product (a consulting/portfolio site). Several course dimensions genuinely don't apply here for that structural reason, not because the practice is missing — this repo's own `docs/ai/agentic-caucus/governance-coverage.md` makes exactly this same distinction for a different standard (a six-layer AI governance model), which is reassuring: the ecosystem already has a documented habit of naming what doesn't apply rather than silently skipping it. Where the comparison *does* apply — evaluation rigor, agent orchestration (Sense/Plan/Act), and matching AI approach to task complexity — the ecosystem meets or exceeds what the course teaches.

## Recommendations

- **Module 2 / 4D Method / 3P Framework (all Gap or N/A)** — no action needed *unless* Sugartown's own roadmap ever adds an AI-facing feature for site visitors (e.g. an AI chat concierge, personalized content recommendations). If that happens, these three dimensions become directly actionable and this audit should be re-run against that feature specifically, not against the internal tooling.
- **5-Question Framework** — if AI-feature work is ever scoped, consider borrowing the pain-severity/market-impact scoring discipline for that specific epic's Background section, rather than building a parallel Linear-priority system.
- **4 AI Design Patterns** — no close-the-gap action; flagged as an interesting parallel worth being aware of, not a deficiency.
- **Context vs. Behavior Matrix** — no action needed; the Model & Mode escalation rule already captures the "don't over-invest by default, escalate on real difficulty" principle the course teaches for a different axis.
- **Nothing to recommend for the two Match dimensions** (Agent Stack, Evaluation rigor) beyond noting they're a genuine strength worth preserving as the ecosystem evolves.

## Framing caveats

- **The comparison itself has a structural mismatch.** The course trains PMs to ship AI *inside* a product for customers; Sugartown's ecosystem uses AI *to build* a product that has no AI-facing features. Several Gap/N/A verdicts above are a direct consequence of that mismatch, not evidence of an immature practice. This mirrors a pattern the ecosystem has already documented for itself: `docs/ai/agentic-caucus/governance-coverage.md` explicitly marks entire layers of a six-layer AI governance model "Not applicable by design" for the same underlying reason (no model training, no inference served to end users) — this audit is applying the same honesty to a different standard.
- **Evidence quality on the standard side is partial.** The Maven course page was fetched via WebFetch, which likely surfaced marketing copy and syllabus headlines rather than a full week-by-week rubric (the page may gate detailed curriculum behind enrollment). The 11 dimensions above are the named frameworks and module titles the fetch actually returned — treat this as a reasonably faithful but not exhaustive extraction of the course's real content.
