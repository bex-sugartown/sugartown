6. Component choice audit

No new component. A Heading component was considered and rejected: every heading is rendered by a Portable Text serializer (richTextComponents.jsx:15-17, ContentBlock.jsx:16-17, PageSections.jsx:92-95, lib/portableTextComponents.js:94-97) or a page template, and composes reaches them all without JSX changes beyond a class name. DS Label was considered for the label sites and rejected: it renders <label htmlFor> (packages/design-system/src/components/Label/Label.tsx) and is only right for form fields.

9. Decisions answered

  1. Mechanism: one shared CSS module consumed by composes, plus two focus tokens. Composite font tokens rejected: they can't carry letter-spacing or case, and they reset font-style. A Heading component rejected (section 6). (2026-11-15, plan approved)
  2. Colour in the bundle: no (2026-11-15, approved as drawn). colour stays at each site, because 3 of 10 h2 sites deliberately use the default text colour.
  3. Platform hub heading italic: dropped (2026-11-15, approved as drawn). Cormorant's italic face ships weights 400 to 500 only, so italic at the bundle's 700 would be synthesised bold.
  4. Page eyebrow case: uppercase (2026-11-15, approved as drawn). The alternative is a named variant that keeps sentence case.
  5. Mobile step: h1 and h2 step one level; h3 steps to --st-font-size-xl (22.4px) so h2 > h3 > body stays ordered on phones (2026-11-15, Bex, revised after Phase 1 showed h2 and h3 both at 28px). Section 2 frames predate this revision. Originally drawn with every level stepping, so article and rich-text headings shrink on phones as page-section headings already do. Cost, visible in section 2: on a phone an h3 drops to the h4 size (18px), the same size as article body text, so it is told apart by weight and family only. ContentBlock and PageSections already render h3 that way today. Alternative: h2 steps, h3 does not.
