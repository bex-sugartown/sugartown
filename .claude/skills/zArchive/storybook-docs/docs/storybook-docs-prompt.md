# PROMPT — Sugartown Storybook Docs Author
**Version:** v1 (2026-06-07)

Run this when adding or updating a Guidelines story for any design system component.

---

## What this skill produces

A complete `[ComponentName].stories.tsx` (or `.jsx`) file with:
- `tags: ['autodocs']` on the meta export (enables sections 02–05 automatically)
- A `Default` story with correctly configured `argTypes` and `args` for the Controls panel
- A `Guidelines` story export containing sections 01 and 06–14
- All doc helpers imported from `helpers/docs.tsx`

## File structure

```
ComponentName.stories.tsx
│
├── Meta (export default)
│   ├── title: "Category/ComponentName"
│   ├── component: ComponentName
│   ├── tags: ['autodocs']            ← enables sections 02–05
│   ├── parameters.layout
│   ├── parameters.docs.description.component   ← one-sentence lead
│   ├── argTypes                      ← see Controls section below
│   └── decorators                   ← [withRouter] if component uses links
│
├── Default story                    ← section 02 live preview with Controls
│   ├── argTypes (story-level)        ← custom controls (titleStyle, tint, etc.)
│   ├── args                          ← default values (reset target)
│   └── render: ({ ...args }) => ...  ← maps args to component props
│
├── Named story exports              ← section 05
│   ├── Default  (required — shown first in autodocs)
│   ├── [VariantA]
│   ├── [VariantB]
│   └── Snapshot (Chromatic VRT — always last, story name exactly "Snapshot")
│
└── Guidelines export                ← sections 01, 06–14
    └── export const Guidelines: Story = {
          parameters: { docs: { disable: true }, controls: { disable: true } },
          render: () => <GuidelinesPage />,
        }
```

## Storybook sidebar categories

Only two categories exist. Do not invent new ones.

| Category | Title format | Use for |
|----------|-------------|---------|
| `Components/` | `Components/ComponentName` | DS primitives — single-responsibility leaf components |
| `Patterns/` | `Patterns/PatternName` | Composite patterns — two or more DS components composed |

Legacy: `Docs/`, `Pages/`, `Foundations/` exist in the sidebar but are not added to by new component stories.

## Controls setup (Default story)

The Controls panel is the live preview for section 02. It must cover every meaningful visual dimension of the component. Follow these rules:

**Suppress raw component props that are replaced by custom controls:**
```js
argTypes: {
  italic:      { table: { disable: true } },  // replaced by titleStyle radio
  media:       { table: { disable: true } },  // replaced by avatarSize select
  breadcrumb:  { table: { disable: true } },  // slot — not a primitive value
  className:   { table: { disable: true } },
}
```

**Use meaningful control types:**
- Enumerated visual states → `radio` (small set) or `select` (large set)
- Boolean flags → `boolean`
- Text that affects layout → `text`
- Color tokens → `select` with token name labels, map to `var(--st-color-X)` in render

**Token select pattern (for any color/tint prop):**
```js
tint: {
  control: { type: 'select' },
  options: ['None', 'Seafoam', 'Midnight', 'Pink', 'Maroon', 'Lime'],
},
// In render:
const tintMap = {
  None:     undefined,
  Seafoam:  'var(--st-color-seafoam-300)',
  Midnight: 'var(--st-color-midnight-300)',
  Pink:     'var(--st-color-pink-300)',
  Maroon:   'var(--st-color-maroon-300)',
  Lime:     'var(--st-color-lime-300)',
}
```

**Before adding a token to a select, verify it exists:**
```bash
grep "token-name" apps/web/src/design-system/styles/tokens.css
```

## Importing doc helpers

From within `.storybook/stories/` (e.g. `EntityDetailPageDocs.stories.tsx`):
```ts
import { DocSection, DoDontGrid, DoGroup, DontGroup, docStyles, ... } from '../helpers/docs'
```

From within `apps/web/src/design-system/components/ComponentName/` (e.g. PageHeader):
```ts
import { DocSection, ..., docStyles } from '../../../../../../apps/storybook/.storybook/helpers/docs'
```
(adjust `../../..` depth to match folder nesting)

**`@sb-helpers` alias** is configured in `main.ts` but only resolves for `.storybook/stories/` files after a full Storybook restart. For `apps/web/` component stories, use the deep relative path — it is more reliable.

## docStyles — canonical page styles

Import `docStyles` from `helpers/docs.tsx` and use it as the `s` object in every Guidelines story render function. Do not define a local `s` object with duplicated values.

```ts
import { docStyles } from '../helpers/docs'
// or for apps/web/ stories:
import { docStyles } from '../../../../../../apps/storybook/.storybook/helpers/docs'

const s = docStyles  // story with no unique layout keys

// or extend for story-specific overrides:
const s = {
  ...docStyles,
  h1:   { fontFamily: 'var(--st-font-family-narrative)', fontSize: '2.25rem', fontWeight: 600, marginBottom: '0.25rem' },
  lead: { color: 'var(--st-color-text-muted)', marginTop: 0, marginBottom: '2rem' },
}
```

**Available keys in `docStyles`:** `page`, `h2`, `h3`, `prose`, `code`, `pre`, `anatomy`, `list`, `a11yList`, `tableWrap`, `table`, `th`, `td`, `tdMono`

## Subdued table pattern

All tables in Guidelines stories use the subdued table pattern. Never use raw `borderCollapse` + custom colors.

```tsx
<div style={s.tableWrap}>
  <table style={s.table}>
    <thead>
      <tr>
        <th style={s.th}>Column</th>
      </tr>
    </thead>
    <tbody>
      <tr>
        <td style={s.td}>Value</td>
        <td style={s.tdMono}>--st-token-name</td>
      </tr>
    </tbody>
  </table>
</div>
```

Token sources:
- `--st-table-wrap-border` — outer border
- `--st-table-header-bg-subdued` — header bg (neutral-200 in light theme)
- `--st-table-header-border-subdued` — header bottom rule
- `--st-table-header-color-subdued` — header label color
- `--st-table-cell-border` — row dividers
- `--st-color-white` — table body bg

## Do / Don't pattern

Use `DoDontGrid` / `DoGroup` / `DontGroup` from `helpers/docs.tsx`. Never write inline `ddGrid`/`ddCol`/`ddHd` styles.

```tsx
<DoDontGrid>
  <DoGroup>               {/* or label={<>Custom <code>label</code></>} */}
    <ul style={s.list}>
      <DoItem>Correct usage.</DoItem>
    </ul>
  </DoGroup>
  <DontGroup>
    <ul style={s.list}>
      <DontItem>Incorrect usage.</DontItem>
    </ul>
  </DontGroup>
</DoDontGrid>
```

For pre/code blocks inside Do/Don't:
```tsx
<DoGroup>
  <pre style={{ ...s.pre, margin: 0 }}>{`code here`}</pre>
</DoGroup>
```

## Authoring rules per section

### 01 — Overview / Purpose
```tsx
<DocSection n="01" title="Overview / Purpose" priority="must">
  <h3 style={s.h3}>What it is</h3>
  <p style={s.prose}>One sentence: [ComponentName] is the [noun] that [verb phrase] on [location].</p>
  <h3 style={s.h3}>What it does</h3>
  <ul style={s.list}>
    <OverviewItem>Renders the [element] — [why it matters]</OverviewItem>
  </ul>
  <h3 style={s.h3}>What it is not</h3>
  <ul style={s.list}>
    <NotItem>Not a [similar component] — use [alternative] for [use case]</NotItem>
  </ul>
</DocSection>
```

### 06 — Usage Guidelines
```tsx
<DocSection n="06" title="Usage Guidelines" priority="must">
  <DoDontGrid>
    <DoGroup><ul style={s.list}><DoItem>...</DoItem></ul></DoGroup>
    <DontGroup><ul style={s.list}><DontItem>...</DontItem></ul></DontGroup>
  </DoDontGrid>
</DocSection>
```

### 07 — Accessibility
```tsx
<DocSection n="07" title="Accessibility" priority="must">
  <ul style={s.a11yList}>
    <A11yItem label="Semantic HTML">The root element is a [element].</A11yItem>
    <A11yItem label="ARIA attributes">[aria-attribute] is set to [value] when [condition].</A11yItem>
    <A11yItem label="Focus behaviour">[ComponentName] is [interactive/non-interactive].</A11yItem>
    <A11yItem label="Colour contrast">All text tokens guarantee WCAG AA (4.5:1).</A11yItem>
    <A11yItem label="Motion">No animations. prefers-reduced-motion has no effect.</A11yItem>
  </ul>
</DocSection>
```

### 08 — Design Tokens
Use `TokenGroup` / `TokenRow` helpers — they apply the subdued table style automatically.
```tsx
<DocSection n="08" title="Design Tokens" priority="must">
  <TokenGroup label="Colour & Surface">
    <TokenRow token="--st-token-name" value="#HEX or alias" role="What it drives" />
  </TokenGroup>
</DocSection>
```

### 09 — Anatomy
```tsx
<DocSection n="09" title="Anatomy" priority="should">
  <pre style={s.anatomy}>{`
┌──────────────────────────┐
│ .root                     │
│  .inner                   │
└──────────────────────────┘
  `.trim()}</pre>
</DocSection>
```

### 13 — Related Components
```tsx
<DocSection n="13" title="Related Components" priority="should">
  <div style={{ display: 'grid', gridTemplateColumns: 'repeat(2, 1fr)', gap: 14 }}>
    <RelatedCard name="ComponentName" why="Why it's related." when="When to use it instead." />
  </div>
</DocSection>
```

### 14 — Changelog
```tsx
<DocSection n="14" title="Changelog" priority="should">
  <ChangelogEntry version="vX.Y.Z" date="YYYY-MM-DD">
    <ChangelogItem breaking>Breaking change description.</ChangelogItem>
    <ChangelogItem>Feature or fix description.</ChangelogItem>
  </ChangelogEntry>
</DocSection>
```

## DocSection props

| Prop | Type | Default | Notes |
|------|------|---------|-------|
| `n` | string | required | Section number, e.g. `"01"` |
| `title` | string | required | Section title |
| `priority` | `'must' \| 'should'` | required | Controls badge colour if shown |
| `showBadge` | boolean | `false` | Only pass `showBadge` on the Story Template reference page |

## Invariants (blocking)

- Do not use `@sb-helpers` alias in `apps/web/` component stories — use the deep relative path.
- Do not define a local `s` object that duplicates keys from `docStyles`.
- Do not use inline `ddGrid`/`ddCol`/`ddHd` style objects — use `DoDontGrid`/`DoGroup`/`DontGroup`.
- Do not write raw `<table style={{ borderCollapse: 'collapse', ... }}>` — wrap in `s.tableWrap` and use `s.table`.
- `DocSection` `showBadge` is false by default — do not pass it in component Guidelines stories, only in the Story Template.
- Imports must be at the top of the file. Never place an import in the middle of JSX.
- The `Guidelines` story must set `parameters: { docs: { disable: true }, controls: { disable: true } }`.

## Execution sequence

1. Read the component source file and existing stories file (if any)
2. Copy `stories.boilerplate.tsx` as the starting point
3. Fill in meta: title (Components/ or Patterns/), component reference, one-sentence lead
4. Configure `Default` story argTypes for all visual dimensions
5. Write named variant stories (Default, [VariantA], Snapshot)
6. Write `GuidelinesPage` render function using DocSection + docStyles
7. Fill sections 01–08 (merge gate); stub 09–14 with `[TODO]` placeholders
8. Verify: `pnpm --filter storybook build-storybook` must succeed with no errors
