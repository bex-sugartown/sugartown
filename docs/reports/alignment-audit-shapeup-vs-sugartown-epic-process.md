# Alignment Audit — Sugartown Epic/PM Process vs. Shape Up

**Date:** 2026-07-01
**Standard source:** [basecamp.com/shapeup](https://basecamp.com/shapeup) — Ryan Singer / Basecamp's product development methodology (Shaping, Betting, Building, Cool-down)
**Scope of ecosystem reviewed:** `docs/epic-template.md`, `CLAUDE.md` (Epic close-out sequence, Multi-phase epic merge cadence, Linear Done = code on main), `docs/backlog/sugartown-backlog-priorities.md`, and observed epic behavior across recent shipped epics (SUG-152 → SUG-204 continuation, SUG-198 → SUG-203/SUG-202 spinoffs, SUG-192).

## Summary

13 dimensions extracted from Shape Up; 3 Match, 4 Drift, 6 Gap. This is a genuinely mixed result, and the split is informative rather than damning: the **wins cluster around discipline that protects shipped quality** (de-risking before commit, "done means deployed," shaping feedback into new tickets instead of scope-creeping the current one). The **losses cluster around time-boxing and decisiveness** — nothing in this repo enforces a fixed appetite, a circuit breaker, or a cool-down, and the backlog is explicitly the opposite of what Shape Up recommends (a long, carefully maintained list, not a place where unimportant ideas are allowed to die). That's a coherent, nameable gap, not a scattershot one — which is exactly the kind of finding worth taking into a next-role conversation: it's a specific practice to adopt, not a vague "be more agile."

## Findings

| Dimension (from standard) | Verdict | Evidence | Notes |
|---|---|---|---|
| Appetite (fixed time budget, not an estimate) | Gap | — | No field in `docs/epic-template.md` sets a time budget for an epic. Epics run until done, however long that takes (SUG-152's Phases 1–2/6b shipped, Phases 3–10 deferred indefinitely to SUG-204 rather than being bounded by a pre-set appetite). |
| Pitch document (problem, appetite, solution, rabbit holes, No Gos) | Drift | `docs/epic-template.md` Background/Scope/Phases sections; "Non-Goals" section (seen in SUG-191's epic doc) | Four of five pitch elements are present and enforced (problem, solution, phases, explicit exclusions via Non-Goals ≈ Shape Up's "No Gos") — appetite is the missing piece, consistent with the Gap above. |
| Shaped work properties (rough, solved, bounded) + de-risking rabbit holes | Match | `CLAUDE.md` "Incomplete epic doc hard stop"; `docs/epic-template.md` Pre-Execution Completeness Gate, App.jsx routing pre-flight | This is close to verbatim Shape Up: an epic with a `TODO` Background, undefined Phases, or an unverified page-route list is explicitly blocked from execution — the hard stop exists specifically to catch unbounded/unsolved work before commitment, which is the whole point of de-risking rabbit holes. |
| Six-week fixed cycles | Gap | — | No fixed cycle length anywhere in the process. Epics range from same-session (SUG-192) to multi-day/multi-phase (SUG-63, referenced in the Multi-phase merge cadence rule) with no standard duration. |
| Cool-down (two-week dedicated break for bugs/planning) | Gap | `CLAUDE.md` "Clean tree" step (Epic close-out Step 9) | The clean-tree requirement is a *micro* cool-down (nothing carries over between epics), but there's no dedicated period for ad-hoc bug fixing or planning between epics — the next epic starts as soon as the last one closes. |
| Betting table (stakeholder funding decision) | Drift | `docs/backlog/sugartown-backlog-priorities.md` header note: "Linear is the single source of truth for prioritization" | A prioritization review happens, but it's a solo self-review against a priority-tag system (🔴🟢🟣⚪⬛), not a multi-stakeholder meeting weighing competing bets. Same function, no counterparty. |
| No backlogs (ideas live decentralized; unimportant ones die) | Drift (a real loss, but likely a deliberate one) | `docs/backlog/sugartown-backlog-priorities.md` — a single, long, actively maintained priority list going back many epics | This is a direct philosophical inversion of Shape Up, not a gap in executing it. Shape Up's bet is that a maintained backlog accumulates guilt and noise; Sugartown's bet is that a maintained backlog is a paper trail and portfolio artifact. Worth naming explicitly as a tradeoff, not silently as a failure. |
| Circuit breaker (default: cancel if not shipped in one cycle) | Gap | SUG-152 → SUG-204 continuation; SUG-198 → SUG-203/SUG-202 spinoffs | The observed pattern is the opposite of a circuit breaker: undone work doesn't die, it gets a new Linear ID and a new backlog doc and stays alive indefinitely. There is no default-cancel behavior anywhere in the process. |
| Team sizing / uninterrupted time (small dedicated team, no context-switching) | Drift | Agent tool subagents, Explore agent, Workflow tool parallel agents | No human team exists to size, so the literal dimension doesn't apply — but the multi-agent orchestration (a design-reviewer subagent, parallel Explore agents, etc.) is a structurally real analog of "a small dedicated crew working one problem," just non-human. Worth noting as a genuine parallel, not forcing a flat N/A. |
| Assign projects, not tasks / "Done means deployed" | Match | `CLAUDE.md` "Linear Done = code on main" rule, with an explicit anti-pattern example ("A branch that exists at origin/<branch> but is not merged into main is not shipped") | This is close to a verbatim match — Shape Up's "done means deployed" and Sugartown's "Done ≠ merged to a feature branch, Done = on main" are the same rule in different words, enforced with a named failure mode. |
| Scopes / scope mapping / hill charts (visual progress tracking) | Gap | — | Epics use flat Phase lists and Linear's coarse status column (Backlog/Todo/In Progress/In Review/Done). Nothing tracks the Shape Up distinction between "the unknowns are solved, we're just executing now" (downhill) vs. "we're still figuring out the approach" (uphill) — a phase either isn't started, is in progress, or is done, with no visibility into *which kind* of progress is being made. |
| Must-haves vs. nice-to-haves / scope hammering | Gap | — | No convention marks any part of an epic's scope as cuttable under time pressure. Scope items in the template are presented as a flat, uniformly-required list. |
| Feedback needs shaping (don't action immediately — shape it for the next cycle) | Match | The "Incomplete epic doc hard stop" combined with the Content Write Gate; observed practice of spinning discovered work into a fresh backlog doc (e.g. SUG-198 surfacing SUG-202/SUG-203 as new tickets rather than expanding SUG-198's own scope) | When new work is discovered mid-epic, the process is to open a new Linear issue and a new backlog doc, not to smuggle it into the current epic's scope. That's exactly Shape Up's "shape feedback into its own pitch" discipline, even though the vocabulary differs. |

## Recommendations

- **Add an Appetite field to `docs/epic-template.md`.** Even a rough one ("small: same session," "medium: 2-3 sessions," "large: needs its own week") would close the biggest single gap and give the Multi-phase merge cadence rule a real trigger for when to invoke it, instead of discovering an epic is oversized after the fact (as happened with SUG-63 and SUG-152).
- **Consider a lightweight circuit breaker.** Not necessarily "cancel by default," but an explicit rule for when a deferred phase becomes its own epic vs. when it should just be dropped — right now every deferral becomes a new ticket (SUG-204, SUG-203, SUG-202), and it's worth asking whether all of those were worth keeping alive.
- **The "no backlogs" Drift is not a recommendation to change** — flagging it as a deliberate, defensible tradeoff (paper trail > backlog hygiene) is more useful than pretending it's accidental. If anything, name this tradeoff explicitly in `CLAUDE.md` alongside the other documented process decisions, the same way the AI governance docs name their own scope boundaries.
- **Hill-chart-style progress signaling** could be cheap to add without a new tool: a one-line "uphill (still solving the approach) / downhill (just executing)" note per Phase in the epic doc would give a lot of the value without building tooling.
- **Must-have/nice-to-have marking** is a low-cost addition — even just a `~` prefix on Scope items that are droppable under time pressure, mirroring Shape Up's own notation, would let an epic actually flex under a real appetite once one exists.

## Framing caveats

- Shape Up is written for a multi-person product team with a founder/stakeholder betting table; several dimensions here (team sizing, betting table) don't have a literal equivalent for a solo AI-assisted practitioner, and the "Drift" verdicts on those reflect an analog, not a failure to implement the real thing.
- The "no backlogs" finding is the one place in this audit where "Drift" shouldn't be read as "needs fixing" — it's a values difference (portfolio/paper-trail vs. backlog-hygiene) that's worth being explicit about rather than treating every Drift the same way.
